# 다시봄 평가

저장소 [README](../README.md)에서 옮겨 온 평가 원문입니다.

## 숫자로 보면

모두 가상 데이터로 잰 값입니다.

| 무엇을 봤나 | 결과 |
|---|---|
| 시연 환자 | 127명(가상) |
| 시연 날 아침, 오늘 연락할 환자 | 27명 |
| 일부러 섞어 둔 '안 온 환자' 19명 | 19명 모두 맞는 자리(오늘 목록, 재연락 대기, 간호팀 확인, 수신 거부)에 나옴 |
| 따로 계산해 둔 예상 결과와 같은 항목 | 540개 중 540개 |

예상 결과도 AI가 짠 계산입니다. 두 계산이 서로 같다는 뜻이고, 정답이 확인됐다는 뜻은 아닙니다.

## 기준과 단서

기준은 구현 전 PRD(설계 문서) v0.1 6절에 적었고, v0.2에서 분자·분모를 구현에 맞게 다시 적었습니다.

**모든 숫자는 합성 데이터 기준입니다.** 데이터·기대값·코드를 같은 도구(Claude Code)로 만든 편향이 있습니다. 기대값 표는 앱 엔진을 쓰지 않은 파이썬 대조 계산이지만, 이것도 AI가 썼습니다. **오너가 달력으로 확인한 행은 0행**입니다.

- 변이 검사는 코드에 일부러 버그를 심어, 테스트가 잡는지 확인하는 방법입니다.
- **30일 연락 수**(기준 166건, v0.2는 183건)는 실제 연락량 예측이 아닙니다. 규칙 값에 따른 차이를 보는 모형입니다. v0.2의 환자 120명만 보면 183 → 150건이고, 거의 전부가 14일 넘게 빠진 주사 회차가 코디네이터 연락 대신 간호팀 확인으로 간 몫입니다. 새 심은 사례 7명이 +16건입니다.
- 이 모형의 가정 세 줄은 화면에 적었습니다. 예정 내원은 예정일에 옴. 미방문·유예 중 환자는 오지 않고 늘 부재(예약한 시점은 예약 날짜에 옴). 목록 줄은 그날 모두 연락.
- 테스트 352개가 통과합니다(`npm test`, v0.2는 289개). 테스트와 기대값도 Claude Code가 썼습니다.
- **독립 대조.** 규칙 문장만 보고 다시 계산하는 별도 계산기를 만들었습니다(엔진·기대값 계산기 코드를 읽지 않음, Claude Code가 씀). 실제 데이터 126명(P127을 더하기 전)의 772개 시점에서 엔진과 불일치 0이었습니다.
- 데이터에 없는 경계 사례 28명에서는 두 건이 갈렸습니다. 엔진 쪽 한 건(14일 넘게 지난 뒤 앞날로 잡은 예약이 재시작을 가림)은 고쳐 P127로 심었습니다. D01 문장 쪽 한 건(관리 안내·주사 재예약의 '연락 기록'이 수신 거부 기록도 포함하는 듯 읽힘)은 문장을 고쳤습니다. 같은 AI가 규칙을 읽었으니 같은 오해를 했을 수 있습니다.

## 재지 않은 것

- 단순 표 계산("수술일 + N일")과의 비교 기준선. "엑셀로 되지 않나"에 답할 숫자가 없습니다.
- 오탐률을 따로 잰 지표(대조군 8명을 심은 사례 안에서만 봄).
- 실제 병원의 연락량, 재방문율, 처리 시간.
