# 다시봄 PRD

> 이 문서는 **구현을 시작하기 전에** 썼습니다. 저장소의 첫 커밋은 코드가 아니라 이 문서입니다. 주제는 "하나 더 할 만한 프로젝트"를 찾아 달라는 제 요청에 따라 Claude Code가 이전 조사의 후보 중에서 골라 제안했고, 초안도 Claude Code가 썼습니다. 채택 여부와 기준값은 제 몫입니다. 확인한 사실에는 근거를, 추론에는 [추론]을, 확인하지 못한 것에는 "미확인"을 붙였습니다.

## 1. 한 줄 정의와 문제

**다시봄은 수술·시술 뒤 정해진 관리 시점과 재방문 일정을 환자별로 계산해, 직원에게 "오늘 연락할 환자" 목록을 만들어 주는 사후관리 도구입니다. 연락 문구는 병원이 승인한 안내문에서만 가져오고, 보내는 것은 사람입니다.**

모발 치료는 오래 봅니다. 수술 뒤에는 며칠, 몇 주, 몇 달, 1년에 걸쳐 관리 시점이 있고, 주사 치료는 정해진 간격으로 여러 번 옵니다. 누가 언제 올 차례인지, 누가 예정일을 넘기고도 오지 않았는지를 사람의 기억이나 표 계산으로 챙기면 빠지는 사람이 생깁니다[추론]. 예정일에 오지 않은 환자에게 병원이 먼저 연락하는 일은 치료 결과와 신뢰 모두에 닿습니다[추론].

다시봄은 이 일을 규칙으로 옮깁니다. 병원이 정한 일정 규칙을 문서에서 읽어 환자마다 1년 일정을 만들고, 오늘 연락할 사람을 이유와 함께 목록으로 보여 주고, 연락 결과를 적으면 다음 연락일을 다시 계산합니다.

**다른 두 프로젝트와의 관계.** 한창구가 환자가 **먼저 보내는 문의**를 다룬다면, 다시봄은 **병원이 먼저 거는 연락**을 다룹니다. 같은각도는 그 방문에서 경과 사진을 같은 조건으로 찍게 합니다. 세 도구는 가상 의원 '샘플의원'의 같은 문서를 씁니다.

## 2. 목표와 이번 범위

### 목표

- 병원 문서(볼트)에 적힌 일정 규칙을 읽어 환자별 관리 일정을 계산한다. 휴진일에 걸리면 다음 진료일로 미루고, 미뤘다는 사실을 표시한다.
- 기준 시각의 "오늘 연락할 환자"를 이유별로 묶어 보인다: 예정일 지남(미방문), 내일 내원 안내, 관리 시점 안내, 주사 재예약, 경과 사진 회차.
- 연락 결과(통화함, 부재, 문자 보냄, 다음에)를 적으면 다음 연락일을 규칙대로 다시 계산한다.
- 연락 문구는 볼트의 승인 문구에 날짜·시각 같은 칸만 채워 만든다. 광고성 표현은 막고, 연락하면 안 되는 시간대에는 "시간 맞춰 보내기"로 표시한다.
- 규칙 값을 바꾸면 오늘 목록과 앞으로 30일의 연락 수가 어떻게 달라지는지 미리 보여 준다(도입 전 시뮬레이션).
- API 키 없이 링크 하나로 30초 안에 핵심 장면을 본다.

### 이번 범위에서 하지 않는 것

- **증상 판단.** 연락 기록에 증상 이야기가 적히면 한창구와 같은 규칙으로 "의료진 확인 필요" 표시만 합니다.
- **실제 문자·알림톡 발송.** 문구와 보낼 시각까지만 만듭니다(5절).
- 진료기록·예약 시스템 연동, 로그인, 실제 환자 데이터.

**선택 기능(크레딧이 있을 때만).** 원장이 글로 쓴 인계장("6개월에 안 오면 먼저 전화")을 AI가 일정 규칙으로 바꿔 **제안**하고, 사람이 기존 규칙과의 차이를 보고 승인합니다. 핵심 기능은 AI 없이 동작합니다.

## 3. 사용자와 30초 시연

**30초 시연(채용 심사자, 노트북).** 기준 시각은 월요일 오전 9시로 고정합니다.

| 초 | 장면 |
|---|---|
| 0~6 | 오늘 목록: 이유별 묶음. 맨 위 빨간 칸 "예정일 지남"(예: 6개월 점검 예정일 12일 지남, 연락 2회 부재) |
| 6~13 | 한 환자를 열면 1년 타임라인(지난 방문 완료·미방문, 다가올 시점), 이번 연락 문구(승인 문구 + 날짜 칸), 연락 결과 버튼. "부재"를 누르면 다음 연락일이 규칙대로 바뀐다 |
| 13~21 | **직접 해 보기:** 수술일을 넣으면 1년 일정이 바로 그려지고, 휴진일에 걸린 시점은 "다음 진료일로 미룸"으로 표시된다 |
| 21~27 | **규칙 바꿔 보기:** "미방문 유예 7일"을 3일로 바꾸면 오늘 목록이 몇 명 늘고, 앞으로 30일 연락 수가 어떻게 바뀌는지 보인다 |
| 27~30 | 평가 탭: 손으로 계산한 기대값과 엔진 결과 대조, 심어 둔 미방문 사례를 모두 잡았는지 |

**사용자 A — 코디네이터(주 사용자).** 아침마다 오늘 목록을 위에서부터 처리합니다.
**사용자 B — 원장.** 연락을 여러 번 해도 닿지 않은 환자 목록을 봅니다.

두 사용자 모두 가정한 사용자입니다. 병원 현장 인터뷰나 검증은 하지 않았습니다.

## 4. 요구사항

| ID | 무엇을 | 완료 기준 |
|---|---|---|
| F1 | 합성 데이터: 환자 120명(가명 ID, 시술 유형, 수술일·첫 주사일, 방문 기록, 연락 기록). 한창구의 샘플의원 볼트(진료시간·휴진, 수술 후 관리, 주사 프로그램, 사진 촬영)를 가져오고, 새 문서 '사후관리 연락 규정'(연락 시점, 미방문 유예, 재연락 간격, 최대 시도, 연락 가능 시간대, 승인 문구)을 더한다 | 미방문·휴진일 겹침·월말·연락 여러 번 실패 같은 사례를 일부러 심고, 심은 사례 목록을 데이터 문서에 적는다 |
| F2 | 규칙 읽기 | 규칙은 볼트 문서의 json에서만 읽는다. 값이 빠지거나 깨지면 전체를 멈추고 기본값을 채우지 않는다 |
| F3 | 일정 엔진 | 순수 함수. 기준 시각을 인자로 받고 시계를 직접 읽지 않는다. 한국 시간 기준 날짜 계산. 휴진일이면 다음 진료일로 미루고 사유를 남긴다. "1월 31일 + 1개월" 같은 월말 규칙을 문서에 정해 두고 테스트로 고정한다 |
| F4 | 오늘 목록 | 예정일 지남 → 내일 내원 → 관리 안내 → 주사 재예약 → 사진 회차 순. 한 환자가 여러 이유에 걸리면 한 줄로 합치고 이유를 모두 보인다 |
| F5 | 미방문 감지 | 예정 방문일 + 유예 일수가 지나도 방문 기록이 없으면 "예정일 지남". 재연락 간격이 지나야 다시 목록에 오고, 최대 시도를 넘기면 "원장 확인"으로 옮긴다 |
| F6 | 연락 결과 기록 | 결과를 적으면 다음 연락일을 다시 계산한다. 되돌리기가 있다. 시연 동안 브라우저에만 남는다 |
| F7 | 연락 문구 | 볼트 승인 문구 + 칸(날짜, 시각, 병원 전화)만. 광고 표현 검사는 한창구와 같은 규칙. 연락 가능 시간대 밖이면 "시간 맞춰 보내기"로 표시한다 |
| F8 | 환자 타임라인 | 1년 동안의 시점, 방문 완료·미방문, 연락 기록을 한 줄에 보인다 |
| F9 | 규칙 바꿔 보기 | 규칙 값 하나를 바꾸면 오늘 목록과 앞으로 30일 연락 수의 차이를 보인다. 볼트 원본은 바뀌지 않는다 |
| F10 | 직접 해 보기 | 수술일·시술 유형을 넣으면 일정이 바로 그려진다 |
| F11 | 사진 회차 | 경과 사진 회차에는 같은각도로 찍으라는 안내를 붙인다(연동은 없음) |
| F12 | 시연 모드 | 기준 시각 고정, 화면 위에 "가상 의원 · 합성 데이터" 띠 |
| F13 | (선택) AI 규칙 제안 | 인계장 원문 → 규칙 json 제안 → 기존 규칙과의 차이를 보고 사람이 승인. 크레딧이 있을 때만, 미리 만든 결과로 시연 |

**자르지 않는 것:** F2~F5, F7, F12. **자르는 순서:** F13 → F9 → F8 세부 → F10.

## 5. 설계 결정과 대안

**왜 AI 없이 계산하는가.** 일정은 틀리면 안 되는 숫자이고, 규칙은 병원이 정한 값입니다. 같은 입력에 같은 결과가 나와야 하고, 틀렸을 때 어디가 틀렸는지 사람이 따라갈 수 있어야 합니다. 그래서 일정은 결정적 코드로 계산하고, AI는 글로 된 규칙을 json으로 옮기는 **제안**에만 씁니다.

**왜 보내지 않는가.** 병원이 환자에게 보내는 알림톡은 공식 딜러를 통한 발신 등록과 템플릿 심사가 필요하고, 정보성 메시지와 광고성 메시지를 구분하는 규정이 있습니다(조사, 세부 미확인). 이 데모는 문구와 보낼 시각까지 만들고, 보내는 일은 병원이 쓰는 발송 도구와 사람에게 맡깁니다.

**한창구에서 가져오는 것.** 볼트 파서, 광고 표현 검사, 개인정보 가림 규칙은 한창구의 코드를 복사해 쓰고, 복사한 커밋을 주석에 적습니다. 두 저장소를 하나의 패키지로 묶는 일은 이번 범위 밖입니다.

**스택.** 서버가 필요 없어서 Next.js 15 정적 내보내기, TypeScript, vitest, Vercel로 갑니다. 선택 기능(F13)의 AI 결과도 미리 만들어 파일로 둡니다.

## 6. 평가

기준은 미리 적고, 못 미쳐도 그대로 싣습니다. 합성 데이터 기준이고, 데이터와 코드를 같은 도구로 만들었다는 편향이 있습니다.

| 지표 | 분자 / 분모 | 기준 |
|---|---|---|
| 일정 계산 정확도 | 손으로 계산한 기대값과 같은 사례 / 기대값 표의 사례 | 전부 |
| 미방문 누락 | 목록에 오지 않은 심은 미방문 사례 / 심은 미방문 사례 | 0건 |
| 결정성 | 같은 기준 시각으로 두 번 만든 목록이 다른 경우 | 0건 |
| 연락 가능 시간대 위반 | 시간대 밖인데 "지금 보내기"로 표시된 문구 | 0건 |
| 테스트가 결함을 잡는지 | 일부러 심은 변이(휴진일 무시, 월말 규칙 뒤집기, 유예 일수 무시, 재연락 간격 무시)를 테스트가 잡은 비율 | 살아남은 변이도 README에 싣는다 |

**병원 도입 지표(실제로 쓴다면 볼 것):** 예정일 지남 환자 수의 추이, 연락 뒤 재방문율, 연락 한 건 처리 시간, "원장 확인"으로 넘어간 환자 수.

## 7. AI 코딩 툴 사용 방식

| 구분 | 내용 |
|---|---|
| AI(Claude Code)가 한 것·할 것 | 주제 제안, 이 PRD 초안, 합성 데이터·규정 문서 초안, 코드와 테스트 초안, 적대적 검토 |
| 사람(제)이 하는 것 | 진행 결정, 초안의 채택·수정·거부, 일정 기대값 표 검수, 기준 확정, 최종 문장에 대한 책임 |
| 검증 | 일정 기대값은 달력을 보고 손으로 계산한 값으로 둔다. 검수하지 않은 것은 그렇게 표시한다 |

## 8. 리스크와 일정

- **규칙 해석.** "6개월 점검"이 수술일로부터 정확히 몇 날인지, 휴진일이면 앞당길지 미룰지는 병원마다 다릅니다. 이 데모는 "다음 진료일로 미룸" 하나로 정하고 병원에 물을 질문으로 남깁니다.
- **연락 피로.** 규칙대로면 같은 환자에게 연락이 몰릴 수 있습니다. 한 환자는 하루 한 줄로 합치고, 재연락 간격을 둡니다.
- **개인정보.** 실제로 쓴다면 연락 기록도 진료 관련 정보라 보관·접근 규칙이 필요합니다. 데모는 합성 데이터와 브라우저 저장만 씁니다.
- **일정.** 9/28 PRD → 9/29 데이터·엔진 → 9/30 화면 → 10/1 배포·적대 검증. 한창구 마무리가 우선이고, 모자라면 자르는 순서대로 줄입니다.
