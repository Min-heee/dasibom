# 다시봄

**수술·시술 뒤 관리 시점을 병원 문서의 규칙으로 계산해, 코디네이터에게 "오늘 연락할 환자"를 이유와 함께 보여 주는 사후관리 도구입니다. 문구는 병원이 승인한 안내문에 날짜만 채우고, 보내는 건 사람입니다.**

- 일정은 AI 없이 결정적 코드로 계산합니다. 휴진일(일요일·법정 공휴일·추가 휴진)에 걸린 시점은 옮기고 사유를 남깁니다. 병원 문서가 옮길 범위를 정한 시점(D+7 내원, 두피 주사 회차)은 그 범위 안에서만 옮기고, 범위 안에 진료일이 없으면 날짜를 지어내지 않고 간호팀 확인으로 보냅니다.
- 예정일을 넘기고도 오지 않은 환자, 내일 내원할 환자, 안내할 차례인 환자를 한 목록에 모읍니다. 연락으로 풀 수 없는 환자(여러 번 닿지 않음, 14일 넘게 빠진 주사 회차, 날짜를 못 정한 시점)는 '간호팀 확인'으로, 연락을 원치 않는 환자는 '수신 거부'로 따로 뺍니다.
- 규칙 값(유예 일수, 재연락 간격, 최대 시도 등)을 바꾸면 오늘 목록과 30일 연락 수가 어떻게 달라지는지 도입 전에 봅니다.

> 모든 데이터는 합성입니다. 가상 의원 '샘플의원'의 문서와 지어낸 환자 127명만 들어 있습니다(맨 아래 '데이터'). 모델을 한 번도 부르지 않고, API 키도 필요 없습니다.

## 왜 만들었나

모발 치료는 오래 봅니다. 수술 뒤 D+1, D+7, 4주, 6개월, 1년에 경과 진료가 있고, 두피 주사는 2주 간격으로 열 번 옵니다. 이 일정을 사람의 기억이나 표로 챙기면 빠지는 사람이 생긴다고 봤습니다[추론]. 그리고 연락이 끊긴 환자는 문의를 보내지 않습니다. 같은 가상 의원의 문의 도구 [한창구](#세-도구)는 들어온 문의만 다루므로, 이 환자들은 병원이 먼저 찾아야 보입니다.

단순 표 계산("수술일 + 7일")과 다른 점은 세 가지를 노렸습니다. 휴진일에 걸린 날을 옮기고 이유를 남기는 것, 이미 온 환자·연락 간격 전인 환자·여러 번 안 닿은 환자를 가르는 것, 그리고 규칙을 병원 문서에서 읽어 규칙이 바뀌면 목록이 따라 바뀌는 것입니다. 표 계산과 나란히 비교한 숫자는 아직 없습니다(한계).

## 어떻게 동작하나

```
볼트 문서(json) → 규칙·달력 ─┐
합성 환자(방문·연락) ────────┼→ 시점 계산(휴진 이동) → 시점 상태(완료·미방문·유예·예정·예약·날짜 미정) → 오늘 목록 · 간호팀 확인 · 재연락 대기 · 수신 거부
이 브라우저의 연락 기록 ──────┘                                                          ↓
                                                                  승인 문구 + 날짜 칸 → 광고 표현 검사 → 보낼 시각
```

- **규칙은 문서에만.** 진료시간·휴진(V02), 사후관리 연락 규정(D01: 시점, 유예, 재연락 간격, 최대 시도, 연락 시간대, 공휴일 목록, 승인 문구), 적신호(V11), 광고 표현(V15)을 승인된 문서의 json에서 읽습니다. 코드에는 숫자가 없습니다.
- **날짜.** 한국 시간 달력 날짜 문자열로만 셉니다. D+n은 수술일이 D+0, 4주는 28일, N개월은 같은 날짜(없으면 그달 말일). 시점마다 기준일에서 따로 계산합니다. 휴진일이면 옮기는데, 문서가 범위를 정한 시점(D+7: D+6~D+9, 두피 주사 회차: 앞뒤 3일)은 범위 안 다음 진료일 → 범위 안 이전 진료일(앞당김) → 그래도 없으면 날짜 미정(간호팀 확인) 순이고, 범위가 없는 시점은 다음 진료일로 미룹니다. 공휴일은 2026-09~2027-12 목록(출처와 확인일을 문서에 적음)이고, 그 밖은 '공휴일 미확인'으로 표시합니다.
- **미방문.** 방문은 채운 시점 키로 짝짓습니다. 잡힌 날짜 + 유예(시점마다 1~14일)가 지나도 오지 않으면 '예정일 지남', 뒤 시점에 왔으면 '건너뜀'입니다. 지남 이후 연락은 결과와 상관없이 한 번으로 세고(연락 원치 않음·수신 거부 풀기는 세지 않음), 마지막 연락 + 3일부터 다시 목록에 올리며, 3회면 '간호팀 확인'으로 옮깁니다. 두피 주사 회차가 예정일에서 14일을 넘기면 재예약 문구 대신 "의료진 진료 뒤 재시작 — 간호팀 확인"이고, 뒤 회차는 '재시작 전'으로 둡니다.
- **연락 결과.** 통화함·부재·문자 보냄·다음에에 더해, '예약 잡음'(시점과 날짜를 적으면 그날까지 예정일 지남에서 빠지고, 지나도 오지 않으면 다음 날부터 다시 지남), '연락 원치 않음'(모든 연락 목록에서 빠지고 '수신 거부'로 표시, 되돌리기·수신 거부 풀기로 되돌림)이 있습니다.
- **이름.** 연락으로 풀 수 없는 일을 넘기는 곳은 볼트의 역할 체계를 따라 '간호팀 확인'입니다. 인계 절차 문서(V12)의 "진료일에는 그날 담당 간호사에게 업무 메신저로 먼저 알리고", 수술 후 관리 문서(V07)의 "간호팀이 의료진과 확인한 뒤 날짜를 정합니다"를 근거로 삼았고, 볼트에 원장이 맡는다는 문장은 없어 v0.2의 '원장 확인'을 바꿨습니다.
- **문구.** 승인 문구에 날짜·진료시간·병원 전화만 채웁니다. 칸이 비면 만들지 않습니다. 연락 가능 시간대(병원 방침 값 09:00~20:00) 밖이면 "시간 맞춰 보내기"와 보낼 시각을 붙입니다.
- **증상 표시.** 연락 메모에 증상 표현이 있으면 한창구와 같은 적신호 규칙으로 '의료진 확인'만 표시합니다. 직원이 판단하지 않습니다.
- **화면.** 판단은 `src/core`의 순수 함수, 화면에 보일 말은 `src/demo`의 순수 함수가 정하고, 컴포넌트는 그리기만 합니다. 그래서 "버튼 → 기록 → 목록 재계산"을 컴포넌트 없이 시험합니다.

## 안전 원칙

1. **보내는 건 사람.** 발송 기능은 없습니다. 문구와 보낼 시각까지만 만듭니다.
2. **승인 문구만.** 문구는 병원이 승인한 안내문에서만 가져오고 칸만 채웁니다. 의료광고 금지 표현이 있으면 '보내기 막힘'입니다.
3. **규칙이 깨지면 멈춘다.** 문서 json이 빠지거나 깨지면 기본값을 채우지 않고 화면 전체를 멈추고 이유를 보입니다(이 방향이 맞는지는 한계에 적음).
4. **증상은 판단하지 않는다.** 적신호 규칙으로 표시만 하고 인계 절차를 따르게 합니다. 문구에 증상 내용을 넣지 않습니다.
5. **숨기지 않는다.** 기대값이 검수 전이라는 것, 모르는 공휴일, 살아남은 변이, 볼트와 어긋나는 결정을 화면과 문서에 그대로 적습니다.

- 규칙 문장만 보고 다시 계산한 독립 대조(엔진·기대값 계산기 코드를 읽지 않은 별도 계산기, Claude Code가 씀): 실제 데이터 126명(P127을 더하기 전)의 772개 시점에서 엔진과 불일치 0. 데이터에 없는 경계 사례 28명에서 두 건이 갈렸고, 엔진 쪽 한 건(14일 넘게 지난 뒤 앞날로 잡은 예약이 재시작을 가림)은 고쳐 P127로 심었고, D01 문장 쪽 한 건(관리 안내·주사 재예약의 '연락 기록'이 수신 거부 기록도 포함하는 듯 읽힘)은 문장을 고쳤습니다. 같은 AI가 규칙을 읽었으니 같은 오해를 했을 수 있습니다.

### 재지 않은 것

- 단순 표 계산("수술일 + N일")과의 비교 기준선. "엑셀로 되지 않나"에 답할 숫자가 없습니다.
- 오탐률을 따로 잰 지표(대조군 8명을 심은 사례 안에서만 봄).
- 실제 병원의 연락량, 재방문율, 처리 시간.

## 실행 방법

Node `^20.19 || ^22.13 || >=24`.

```bash
npm install
npm run dev        # http://localhost:3000 — 시작 전에 번들을 새로 만든다
npm test           # 테스트 352개
npm run test:tz    # 같은 시험을 America/Los_Angeles·UTC 시간대에서
npm run verify     # test + typecheck + lint + build(정적 내보내기 out/)
npm run preview    # out/을 http://localhost:3200 으로
python3 scripts/mutate-screen.py   # 화면 연결 변이 검사(임시 폴더에 복사해서 돌림, 몇 분 걸림)
python3 scripts/mutate-rules.py    # v0.2.1 규칙 변이 검사(같은 방식, 몇십 분 걸림)
```

`verify` 안의 `next build`는 `npm run dev`와 같은 `.next` 폴더를 씁니다. 개발 서버를 켠 채 돌리면 개발 서버가 깨지니 먼저 끄세요.

**번들.** 정적 내보내기라 브라우저가 파일을 읽지 못하므로, `npm run bundle`이 `vault/`와 `data/`를 `src/generated/`의 JSON 두 개로 묶습니다(화면 번들, 평가 번들). `dev`·`build`·`test`·`typecheck` 앞에서 자동으로 돌고, 생성물은 커밋하지 않습니다.

**데이터 다시 만들기.** `python3 data/scripts/generate_patients.py && python3 data/scripts/followup_expected.py`(시드 고정, 두 번 돌려도 같은 파일).

## 한계

- **휴진 이동 범위는 문서에 적힌 두 시점에만 있습니다.** D+7(D+6~D+9)과 두피 주사 회차(앞뒤 3일)는 범위 안에서 옮기지만, D+1·4주·6개월·1년은 문서에 범위가 없어 여전히 다음 진료일로 미룹니다(며칠까지 괜찮은지는 병원에 물을 질문). 범위 안에서 뒤를 먼저 보고 앞당김을 나중에 보는 순서도 이 도구가 정한 것입니다.
- **데이터를 넣는 길이 없습니다.** 연동도 파일 가져오기도 없어서, 지금 모양으로는 차트에 적은 방문을 한 번 더 입력해야 합니다.
- **예약표가 없습니다.** '예약 잡음'은 이 브라우저의 연락 기록에 적는 것뿐이라, 예약 시스템에만 적힌 예약은 모릅니다. 예약 날짜가 지나면 방문 기록이 들어오기 전까지 다시 '예정일 지남'입니다. 한창구 문의함의 추석 날짜 확정 예약(Q27 등)과도 서로 다른 말을 합니다.
- **수신 거부는 연락 목록에서만 뺍니다.** 증상 메모의 '의료진 확인'은 안전 확인이라 수신 거부 환자에게도 남깁니다. 수신 거부가 법적 수신 동의 철회와 같은 뜻인지는 판단하지 않습니다.
- **문구가 치료 사실을 드러낼 수 있습니다.** 일부 승인 문구에 "수술 다음 날", "두피 주사 회차", "경과 사진" 같은 말이 들어 있습니다. '두피 관리 다음 회차 안내'는 광고성으로 읽힐 여지가 있습니다[추론].
- **4~14일 늦어진 주사 회차의 남은 회차 다시 계산(V08)은 하지 않습니다.** 14일을 넘긴 회차만 재시작(간호팀 확인)으로 보내고, 그 사이의 회차는 지금도 예정일 지남 목록에서 재예약 안내 문구를 씁니다.
- **규칙이 하나만 깨져도 목록 전체가 멈춥니다.** 오전에 목록이 비면 모든 환자를 놓친다는 반대 방향의 위험이 있습니다.
- **기대값이 검수 전입니다.** 540 / 540은 AI가 짠 두 구현(엔진과 파이썬 대조 계산)이 서로 같다는 뜻이지 정답이라는 뜻이 아닙니다. 같은 오해를 함께 가질 수 있습니다.
- **공휴일 목록은 2026-09~2027-12만** 확인했습니다. 임시공휴일은 관보를 보지 않았습니다.
- **볼트의 의료 서술과 D01의 숫자는 의료진 검토를 받지 않았습니다.** 유예 일수, 재연락 간격 3일, 최대 시도 3회, 연락 시간대는 AI가 정한 가상 값입니다.
- **사용자는 가정입니다.** 병원 현장 인터뷰나 검증을 하지 않았습니다.
- **법 검토를 대신하지 않습니다.** 목록과 연락 기록은 건강에 관한 정보로 민감정보일 가능성이 높습니다[추론]. 데모의 연락 기록은 이 브라우저의 localStorage에만 남고 '초기화'로 지웁니다.

자세한 목록과 검토에서 받은 지적의 처리는 [`docs/PRD.md`](docs/PRD.md) 8·10절에 있습니다.

## AI 코딩 툴 사용 방식

이 저장소의 **주제 선정부터** 문서·데이터·코드 초안까지 Claude Code가 했습니다. 숨기지 않고 나눠 적습니다.

| 구분 | 내용 |
|---|---|
| AI(Claude Code)가 한 것 | **주제 선정**: 한창구를 만들던 중의 "그리고 이거 말고 또 할만한 프로젝트좀 해줘"라는 한 줄 요청에, 이전 조사의 후보 중에서 이 주제를 골라 착수까지 했습니다. PRD v0.1·v0.2·v0.2.1, 새 볼트 문서 D01과 공휴일 조사, 합성 환자·기대값 계산기, 코드와 테스트, 적대적 검토(PRD 3건, 화면 1회)와 반영, 변이 검사, 커밋 메시지 |
| 제가 한 것 | 진행 결정과 최종 책임. 기대값 검수와 병원에 물을 질문(PRD 9절)은 아직 하지 않았습니다 |
| 검증 방식 | 사람이 코드를 한 줄씩 읽는 대신, 판단을 순수 함수로 두고 시험·기대값 대조·변이 검사로 확인합니다. 출처가 있는 것만 사실로 적고, 검수하지 않은 것은 화면과 문서에 그렇게 표시합니다 |

- 순서: **PRD v0.1을 첫 커밋으로 쓰고**(코드 없음), 데이터·엔진·화면을 만든 뒤 PRD 적대 검토 3건과 화면 적대 검토 1회를 반영해 PRD를 v0.2로 고쳤습니다. 커밋은 작업 뒤에 성격별로 묶어 나눈 것입니다.
- PRD v0.1은 기대값을 "손으로 계산한 값"이라고 적었는데 틀린 표현입니다. 실제로는 AI가 짠 파이썬 대조 계산이고 v0.2에서 고쳤습니다. 한창구 v0.1에서 한 실수를 반복한 것입니다.
- 한창구(cbf5034)에서 볼트 9편과 코드 네 파일(`vault.ts`, `adcheck.ts`, `redflag.ts`, `mask.ts`)을 복사했고 파일 머리에 적었습니다. `redflag.ts`는 어절 경계를 넘는 적중("붓고 열감"에서 "고열") 한 곳을 고쳤고, 같은 결함이 한창구 원본에도 있습니다.
